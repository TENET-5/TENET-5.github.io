Q# demo online

Research mode

Simulation-first

No hidden services, no black-box cloud dependency, and no inflated claims about deployment readiness.

Purpose

Explainability

The technical goal is clarity: make logic paths, measurement outcomes, and resource tradeoffs visible to the public.

Why this track exists

TENET5 applies the same evidence-first discipline to technical work that it applies to institutional analysis. If a system is worth discussing, it should be inspectable. That means publishing the logic, describing the assumptions, and keeping the demonstrations small enough to verify.

Current public sample

Five-qubit Loom coherence check

This Q# sample creates a simple superposition-led chain across five qubits, then measures the register. It is designed as a public explainability artifact rather than a production algorithm.

Open the Q# source →

import Std.Diagnostics.*; import Std.Measurement.*; operation PrepareLoomState(register : Qubit[]) : Unit is Adj + Ctl { H(register[0]); CNOT(register[0], register[1]); CNOT(register[1], register[2]); CNOT(register[2], register[3]); CNOT(register[3], register[4]); }

Scope and limits

  • No unsupported claims about real-world quantum advantage.
  • No replacement of the site's evidence chain with algorithmic authority.
  • No hidden model calls or opaque hosted tooling required to inspect the examples.
  • All public demos should remain small, reproducible, and technically honest.

Next development path

1. More reference circuits

Bell-state, phase, and measurement examples that help readers understand the fundamentals without overselling the technology.

2. Resource estimation

Visible counts for qubits, depth, and gates so tradeoffs are documented rather than guessed.

3. Explainability overlays

Plain-language interpretation layers so non-specialists can understand what each demo is doing and why it matters.
